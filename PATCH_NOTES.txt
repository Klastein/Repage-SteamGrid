Repage SteamGrid 3.3.4 — Big Picture Navigation & Layout Refinement

Navigation changes
- Big Picture library and page columns are treated as vertical-only regions. Left/Right leave the column directly; Up/Down move through its own live DOM order.
- Entering the content region from the page column now selects the first meaningful control in the active page, excluding the language picker and close button.
- Main content uses semantic groups: row, grid, stack/list. Horizontal moves stay on the same visual row; vertical moves advance to the nearest next visual row or the next page control.
- The page-wide geometric fallback that could jump from a lower column to the language picker has been removed. Horizontal navigation no longer chooses controls on another row.
- The active DOM is re-read for every move, preserving access to dynamically rendered controls and future filter options.
- Personalization now declares explicit navigation scopes for its header, preset grids, package selector, custom preset actions, and color controls.
- Filter cells remain a navigable grid; edge movement is contained rather than jumping to unrelated controls.

Big Picture layout changes
- Filter panel no longer flex-shrinks into a narrow strip above the image grid. It has a bounded scroll area, a responsive minimum column width, and usable control heights.
- Pad hints are kept in normal flow and above the filter surface.

Validation
- JavaScript syntax, JSON metadata, archive integrity, and isolated directional-routing cases were checked.
- The Steam client / Steam Deck Gamepad UI was not available in this environment; native Steam Focusable integration still needs a real controller session.

- Kept the Personalization tab enabled in Big Picture and preserved the current visual layout. Code inspection showed fixable focus-source and navigation-boundary defects, so a full redesign or removal was not necessary.

Fixes

Repage SteamGrid 3.4.3 — Big Picture Gamepad Event Deduplication

Fixes
- Select/Search in Big Picture now has one owner: Steam Focusable's onSelectButton callback. Repage SteamGrid 3.5.3 — Isolated title-logo preview and source fallback

Fixes
- The title preview now queries its own score-ordered static-logo candidate list; it no longer reads or mutates the live gallery catalogue/cache.
- Each candidate is attempted in score order: thumbnail first, then the same artwork's original URL, then the next eligible score. A failed thumbnail no longer permanently hides the top-scoring artwork when its original URL is available.
- A failed preview URL is no longer saved as a negative cache entry for a day; the next visit can retry after transient CDN/network failures.
- Alpha cropping and adaptive fitting operate only on a temporary canvas/data URL used by the sidebar preview. Gallery thumbnails, selected artwork records, and Steam artwork application keep their original URLs and pixels.
- Removed the preview's dependency on the shared backend temporary-download/chunk-cache helper. CORS fallback now uses an isolated browser fetch/blob path, so preview inspection cannot unpin or clean up a temporary file used by the gallery/apply pipeline.

Validation
- JavaScript syntax, JSON metadata, version consistency, and ZIP integrity checked.
- Real Steam client / CDN behavior still requires visual confirmation on the user's setup.


======================================================================
3.5.6 — PREVIEW LOAD PERFORMANCE
======================================================================
- The title logo is now revealed as soon as the browser has loaded the
  selected preview image. Alpha analysis and the isolated backend image
  read run after first paint, instead of delaying the text-to-logo swap.
- Preview images use eager/high fetch priority and no crossOrigin mode,
  avoiding a failed CORS-mode request followed by a second normal request.
  The backend remains responsible for safe pixel analysis of a copy.
- Cached candidate URLs are now served stale-while-revalidate: a saved
  logo remains available immediately, while entries older than seven days
  are refreshed in the background (with a six-hour retry cooldown).
- Normalized previews remain in a bounded in-memory cache and are reused
  immediately when revisiting a game in the same Steam session.
- Gallery fallback, artwork ranking, original artwork URLs, application
  logic, controller navigation, and Lua artwork backend were not changed.
